# 概念：相关包简介（teenycode 用到的 npm 包）

> 目的：读 teenycode 前的依赖清单课。它运行时只依赖两个包：**openai** 和 **zod**。
> 一句话：openai 负责"和模型说话"，zod 负责"校验工具参数 + 生成给模型看的说明书"。

---

## 总览：teenycode 依赖了哪些包

来源：teenycode 的 `package.json`。

| 包 | 版本 | 用途 | 要掌握吗 |
|---|---|---|---|
| `openai` | ^6.49.0 | 官方 SDK，调大模型（chat completions + 工具调用） | ✅ 核心 |
| `zod` | ^4.3.6 | 声明式 schema：校验参数 + 生成 JSON Schema | ✅ 核心 |
| `tsx` | 开发依赖 | 直接跑 .ts 文件（`vp node --import tsx src/index.ts`） | 了解即可 |
| `typescript` / `vite-plus` / `@types/node` | 开发依赖 | 类型检查 / 构建工具链 | 暂不深究 |

## 一、openai — OpenAI 官方 Node.js / TS SDK

npm 包名 `openai`（仓库 openai/openai-node，官方维护，TS 编写自带类型）。
**它把你手写的 fetch + headers + JSON.parse + 错误处理，全部封装成了"一个对象、一个方法"。**

### 1. 安装与初始化

```bash
npm install openai
```

```js
import OpenAI from "openai"        // 默认导出（ESM，teenycode 是 type: module）

const client = new OpenAI()         // ① 自动读环境变量 OPENAI_API_KEY，最省事

// ② 显式指定（想用 DeepSeek 等 OpenAI 兼容服务时）：
const client = new OpenAI({
  apiKey: process.env.DEEPSEEK_API_KEY,
  baseURL: "https://api.deepseek.com",
})
```

> 提示：SDK 还认 `OPENAI_BASE_URL` 环境变量。所以用 DeepSeek 跑 teenycode 不用改代码，
> 设 `OPENAI_BASE_URL=https://api.deepseek.com` + `OPENAI_API_KEY=sk-...` 即可。

### 2. 核心方法：`client.chat.completions.create`

```js
const res = await client.chat.completions.create({
  model: "gpt-5",
  messages: [
    { role: "system", content: "You are helpful." },
    { role: "user", content: "hi" },
  ],
  tools: [...],   // 可选：工具说明书
})
console.log(res.choices[0].message.content)
```

返回的 `res` 就是《简易 DeepSeek 输出格式》那份笔记里的 JSON 结构——**SDK 内部帮你把
fetch、res.json()、解析全做完了**，直接拿到类型安全的 JS 对象。

**与手写 fetch 对照（chat.js / agent.js → SDK）：**

| 手写 | openai SDK |
|---|---|
| `fetch(URL, {headers, body: JSON.stringify(...)})` | `client.chat.completions.create({...})` |
| `await res.json()` 再取字段 | 直接拿对象，如 `res.choices[0].message` |
| `if (!res.ok) throw ...` | SDK 自动抛 `OpenAI.APIError` 子类 |
| 手动拼 `Authorization: Bearer` | 构造 client 时已带上 |

### 3. 工具调用（Function Calling）

- 请求侧：`tools` 参数，格式和 agent.js 里手写的一样（`{type:'function', function:{name, description, parameters}}`）；
- 返回侧：`res.choices[0].message.tool_calls`，每项含：
  - `id`：调用 ID（回喂 `role:'tool'` 消息时要对应它）
  - `function.name`：工具名
  - `function.arguments`：**JSON 字符串**，要 `JSON.parse` 后才是参数对象

### 4. 流式输出（stream: true）

```js
const stream = await client.chat.completions.create({ model, messages, stream: true })
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "")
}
```

`chunk.choices[0].delta` 是增量内容（不是完整回答）。teenycode 用的非流式，但读生产级 agent 会常遇到。

### 5. TypeScript 类型（teenycode 用到了）

```ts
import type { ChatCompletionMessageParam } from "openai/resources/chat/completions";
const messages: ChatCompletionMessageParam[] = [ ... ]  // agent.ts 第 27 行
```

常用类型：`ChatCompletionMessageParam`（messages 元素）、`ChatCompletion`（返回）、
`ChatCompletionTool`（工具）。这也是用 SDK 比手写 fetch 舒服的地方：写错字段名编译期就报错。

### 6. 默认行为与错误处理

- **自动重试**：默认失败重试 2 次（`new OpenAI({ maxRetries })` 可调）；
- **超时**：默认 10 分钟；
- **错误分类**：`OpenAI.AuthenticationError`（key 错）、`OpenAI.RateLimitError`（限流）、
  `OpenAI.APIConnectionError`（网络）…… 都继承 `OpenAI.APIError`，可用 `instanceof` 区分处理。

## 二、zod — 声明式校验库（v4）

npm 包名 `zod`，作者 colinhacks，几乎是 JS/TS 生态的事实标准校验库。
**核心思想：定义一个 schema（模式），它同时能干三件事——校验数据、推断 TS 类型、生成 JSON Schema。**

### 1. 安装

```bash
npm install zod
```

### 2. 核心 API（够读 teenycode 用）

**基础类型（拼 schema 的积木）：**

```ts
import { z } from "zod";

z.string()                      // 字符串
z.number()                      // 数字
z.boolean()                     // 布尔
z.array(z.string())             // 字符串数组
z.object({ path: z.string() })  // 对象：键 = 字段名，值 = 该字段自己的 schema
```

**修饰符（在基础类型上叠加约束）：**

```ts
z.string().optional()          // 可以缺省（缺了为 undefined）
z.string().nullable()          // 可以为 null
z.string().describe("说明文字") // 加描述——转 JSON Schema 时描述会带进去，模型能看到
```

**校验入口：`parse` 与 `safeParse`**

```ts
readFileInput.parse(input)
// 合法：返回类型化后的数据；不合法：直接 throw（程序终止/被 catch）

const result = readFileInput.safeParse(input)
// 永远不 throw；返回 { success: true, data } 或 { success: false, error }
```

**类型推断（一个定义，两处用）：**

```ts
type ReadFileInput = z.infer<typeof readFileInput>
// 从 schema 反推 TS 类型：schema 改，类型跟着改，不会两处失同步
```

**v4 新能力：`z.toJSONSchema()`**

```ts
z.toJSONSchema(schema)
// 直接把 zod schema 转成 JSON Schema（v3 时代要装额外的 zod-to-json-schema 包）
```

### 3. teenycode 里的完整链路（为什么这样设计）

`tools.ts` 第 20~22 行定义一个工具的参数 schema：

```ts
const readFileInput = z.object({
  path: z.string().describe("The relative path of a file in the working directory."),
})
```

这份 schema 在**两个方向**被使用：

| 方向 | 代码 | 作用 |
|---|---|---|
| 给模型看 | `z.toJSONSchema(readFileInput)` → `parameters`（tools.ts 第 156 行） | 模型知道该传什么参数 |
| 给自己校验 | `readFileInput.parse(input)`（tools.ts 第 31 行） | 程序执行前确认参数合法 |

好处：**一份定义，两头用**——模型看到的说明书和程序实际校验的规则来自同一处，不会写两遍对不上。

## 三、两个包怎么协作（理解 teenycode 的关键）

```
模型侧：openai 把 zod 生成的说明书发出去 → 模型回 tool_calls（arguments 是 JSON 字符串）
程序侧：JSON.parse 参数 → zod 校验 → 合法才执行工具
出错时：zod 校验失败 → execute 抛错 → teenycode 把 "ERROR: ..." 回喂给模型（agent.ts 106~110 行）
       → 模型看到错误自己纠正重试（这就是"报错回喂"容错闭环）
```

teenycode 的 `Tool` 类型把这一切统一起来（tools.ts 第 10~15 行）：

```ts
type Tool = {
  name: string;                    // 工具名（模型调用时用）
  description: string;             // 工具说明（模型决定何时用时看）
  schema: z.ZodTypeAny;            // 参数模式（zod）
  execute: (input: unknown) => Promise<string>;  // 真正执行的函数
};
```

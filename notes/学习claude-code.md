# 循环
## 子代理
- **解决什么问题**：保持上下文高效
- **怎么做的**：1. 对于子任务，由主agent生成提示词，交给子代理来完成任务。不需要知道其他的上下文，没有先前的消息历史，尽管它确实加载自己的系统提示和项目级上下文，如 CLAUDE.md。 2. 子代理只获取部分tool的信息。3. 根据任务设置effect-level（权限级别）和effort。4. 调用子代理其实是一次工具调用，主循环会等待子代理返回。
- **取舍（代价）**：它放弃了过多的上下文，代码更复杂。

## 消息类型划分
- **解决什么问题**：更好的管理上下文
- **怎么做的**：
五个核心类型是：
SystemMessage： 会话生命周期事件。subtype 字段区分它们：
"init"：运行的会话元数据。当 SessionStart 或 Setup hook 在会话启动期间运行时，其 hook 生命周期消息 在 init 消息之前到达
"compact_boundary"：在 compaction 后触发
"informational"：来自循环的纯文本状态横幅
"worker_shutting_down"：循环将在当前轮次后结束，因为主机正在退出或 Remote Control 已断开连接
在 TypeScript 中，除了 "init" 之外的每个 subtype 在 SDKMessage union 中都是其自己的类型，而不是 SDKSystemMessage 的子类型。
AssistantMessage： 在每个 Claude 响应后发出，包括最终仅包含文本的响应。包含该轮次的文本内容块和工具调用块。
UserMessage： 在每个工具执行后发出，包含发送回 Claude 的工具结果内容。也为你在循环中间流式传输的任何用户输入发出。
StreamEvent： 仅在启用部分消息时发出。包含原始 API 流事件（文本增量、工具输入块）。请参阅 Stream responses。
ResultMessage： 标记代理循环的结束。包含最终文本结果、令牌使用、成本和会话 ID。检查 subtype 字段以确定任务是否成功或达到限制。少数尾随系统事件（如 prompt_suggestion）可能在其后到达，因此迭代流直到完成，而不是在结果处中断。请参阅 Handle the result。

- **我的 fork 有没有**：没有，我们直接使用openai的格式来管理上下文，使用rule字段进行区分。这样做简单粗暴，但是缺点就是不好管理哪些内容应该被显示到界面上，哪些应该被删除（这种简单粗暴的方式，不要的文字只能直接不加入到上下文当中），但是现在项目结构简单，还没有必要做消息类型划分。

## 权限模式
- **解决什么问题**：方便进行权限管理
- **怎么做的**：

模式	行为
"default"	不被允许规则覆盖的工具触发你的批准回调；没有回调意味着拒绝
"acceptEdits"	自动批准文件编辑和常见文件系统命令（mkdir、touch、mv、cp 等）；其他 Bash 命令遵循默认规则
"plan"	Claude 探索并规划而不编辑你的源文件；文件编辑永远不会自动批准，并通过你的 canUseTool 回调提示
"dontAsk"	从不提示。由 权限规则 预批准的工具运行；其他一切被拒绝。AskUserQuestion、连接器工具 你的组织设置为 ask 和标记为 requiresUserInteraction 的 MCP 工具即使你已允许它们也会被拒绝
"auto"	使用模型分类器批准或拒绝每个工具调用。有关可用性和行为，请参阅 自动模式
"bypassPermissions"	运行所有允许的工具而不询问，除了由显式 ask 规则 匹配的工具、连接器工具 你的组织设置为 ask 和需要用户交互的工具；有关优先级顺序，请参阅 权限如何被评估。在 Unix 上以 root 身份运行时无法使用。仅在隔离环境中使用，其中代理的操作无法影响你关心的系统

## OpenTelemetry
- **解决什么问题**：将来自 Agent SDK 的跟踪、指标和事件导出到您的可观测性后端。方便了解agent运行的情况，比如平均每个任务消耗多少token。
- **怎么做的**：Agent SDK 将 Claude Code CLI 作为子进程运行，并通过本地管道与其通信。CLI 内置了 OpenTelemetry 检测：它在每个模型请求和工具执行周围记录跨度，为令牌和成本计数器发出指标，并为提示和工具结果发出结构化日志事件。SDK 本身不产生遥测数据。相反，它将配置传递给 CLI 进程，CLI 直接导出到您的收集器。通过3个信号进行导出。

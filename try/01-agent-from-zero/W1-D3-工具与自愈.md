> **前置**：W1-D1 的 `agent.js` 整合版（你的 110 行版本）；W1-D2 读 teenycode（错误回喂）
> **产出**：`agent.js` 升级版——能读文件、能跑命令、出错能自愈
> **预计**：2~3 小时

## 目标

1. 给 `agent.js` 加 `read_file`、`run_command` 两个工具——从"只会报时"变成"能干活"；
2. 用上 W1-D2 从 teenycode 学到的**错误回喂**：工具出错不再崩溃，而是让模型自己修；
3. 体会"观察-反馈"闭环（理论 #1）：模型读文件 → 看到真实内容 → 再决策。

## 一、为什么（先看为什么）

你现在的 `get_current_time` 是个"哑工具"：结果固定、没有副作用。而真实 agent 的核心工具是**读写文件、跑命令**——有了这两个，模型才能"看代码 → 改代码 → 验证"。

对照 teenycode（你已经读过的 `source/teenycode/src/tools.ts`）：它有 `read_file` / `list_files` / `edit_file` 三个工具。我们这一课先做**读**（`read_file`）和**跑**（`run_command`），编辑留到 W1-D4 之后（等验证回路到位，改了才能验证）。

## 二、动手：三个改动（改你自己的 agent.js）

### 改动 1：tools 数组加 `read_file` 的说明书

```js
{
  type: 'function',
  function: {
    name: 'read_file',
    description: '读取指定路径的文件内容并返回。回答文件内容相关的问题时必须调用，不要凭记忆猜测。',
    parameters: {
      type: 'object',
      properties: {
        path: { type: 'string', description: '要读取的文件路径' },
      },
      required: ['path'],
    },
  },
}
```

注意两个细节：
- `required: ['path']`——告诉模型"这个参数必须给"，不给就会解析失败；
- `description` 里写了"不要凭记忆猜测"——这是在引导模型**用工具而不是幻觉**（防幻觉靠提示词的第一线）。

### 改动 2：runTool 加 case，并给主循环加"错误回喂"

先在 `runTool` 里加分支（顶部加 `const fs = require('node:fs')`）：

```js
case 'read_file': {
  const { path } = args
  return fs.readFileSync(path, 'utf8')
}
case 'run_command': {
  const { command } = args
  return require('node:child_process').execSync(command, { encoding: 'utf8', timeout: 10000 }).trim()
}
```

然后给主循环里的工具调用包上 try/catch——**这是本课的核心改动**，把 W1-D2 学的"错误回喂"落地：

```js
// 改之前（你的版本）：出错就 throw，整个程序崩掉
for (const tc of msg.tool_calls) {
  const result = runTool(tc.function.name, JSON.parse(tc.function.arguments))
  messages.push({ role: 'tool', tool_call_id: tc.id, content: String(result) })
}

// 改之后（teenycode 版本）：错误变成字符串，回喂给模型自愈
for (const tc of msg.tool_calls) {
  let result
  try {
    result = runTool(tc.function.name, JSON.parse(tc.function.arguments))
  } catch (err) {
    result = `ERROR: ${err.message}`   // ← 关键：错误不是终点，是下一轮"想"的输入
  }
  messages.push({ role: 'tool', tool_call_id: tc.id, content: String(result) })
}
```

### 改动 3：跑命令的安全意识（先记着）

`run_command` 现在**裸跑任意命令**——模型说什么就执行什么，非常危险。W1-D6 我们会加权限门控（危险命令先问你）。练习阶段只在测试目录里跑无害命令（`node --version`、`ls`、`echo` 之类），**别让它在你的真实项目目录里乱跑**。

## 三、测试剧本（三个具体实验）

改完依次跑，每个都观察行为：

1. **读文件**：`node agent.js "读一下 agent.js 的前几行，告诉我这是什么"` —— 模型应该调用 `read_file`，然后基于真实内容回答；
2. **跑命令**：`node agent.js "运行 node --version，告诉我 Node 版本"` —— 模型调用 `run_command`，报告结果；
3. **自愈测试（重点）**：`node agent.js "读一下 xxx.txt 并告诉我内容"`（xxx.txt 不存在）
   - 改之前：程序崩溃（throw 冒到 main 的 catch，直接退出）；
   - 改之后：模型收到 `ERROR: ENOENT...` → 它会**自己调整**（比如改成查找真实文件名，或者诚实地说"文件不存在"）。
   - 亲眼看到这个差别，就是本课最大的收获。
